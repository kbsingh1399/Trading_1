4.3 Intelligence Score


The composite blends five components: bias magnitude (35%), 24h elite flow momentum (25%), elite-crowd


divergence beyond 30 points (15%), 1h flow agreement with the 24h direction (15%), and funding headroom


when the extreme argues against the crowd (10%). Two governors keep the leaderboard honest: whale


concentration above 50% caps conviction, and a liquidity damper scales scores by tradeable volume so that


unpriceable or illiquid rows sink instead of dominating. Direction is neutralized whenever the asset has no


mark price or the elite bias is within 5 points of zero.

5 System Architecture


The architecture is five strict layers with one-way dependencies: sources, ingestion, the intelligence core,


storage, and serving. Each layer is a Python package that can be unit-tested without the ones below it - the


intelligence core in particular is a set of pure functions over plain dictionaries, which is why the entire


feature/signal suite runs in 0.16 seconds with no network.


Two deliberate choices deserve explanation before the diagram. In-process hot state: the dashboard reads


from a bounded in-memory store rather than querying ClickHouse on every request, keeping p99 read


latency in the microseconds and eliminating a whole class of partial-failure states; ClickHouse exists for


durability, backtesting and post-mortems, and writes asynchronously. All-in-one process: the reference stack


embeds the ingestion supervisor inside the API container - one process, one log stream, one thing to babysit -


while the same components split into separate api and ingest workers by changing one environment variable


when the volume outgrows a single host.

6.1 Resilience and warm-up honesty


Every network call retries with exponential backoff and distinguishes rate limits, WAF soft blocks and


genuine errors; failed loops retry after 60 seconds instead of waiting out their full interval. Flow windows


have a warm-up property the system refuses to fake: during the first hour after deployment, a “1h” flow is


really the change since the oldest available snapshot, and every signal message labels the true elapsed window


(for example “over 5m”) until genuine 1h/4h/24h history exists. The 7-day backfill on boot covers cohort


positioning at universe level, while per-market windows build from the system's own snapshots - the only


source of per-coin history, since no discovered API exposes it.


7 Storage and Schemas


Storage is a narrow interface with two interchangeable backends. MemoryStore keeps bounded deques (7


days of minute-level snapshots) plus a latest-record map - it exists so the stack runs with zero infrastructure


and so unit tests never touch a database. ClickHouseStore mirrors every append into MergeTree tables with


partitioned TTLs; the hot read path still serves from process memory, so ClickHouse being briefly


unavailable never degrades the dashboard.

9.1 Scale-out path


Growth pressures the design in a predictable order, and each step is a seam that already exists. First, split the


supervisor from the API by setting HD_RUN_MODE=api and running python -m hd_intel.scheduler as a


second container pointed at the same ClickHouse - no code changes. Second, shard ingestion: the


participation poller is already a pure function of its inputs, so N worker replicas can each own a slice of the


Tier-1 universe behind a Redis or Kafka work queue. Third, when per-wallet fill mirroring arrives, replace


the polling loops with Hyperliquid WebSocket subscriptions and keep the identical feature layer - the


intelligence core never learns where its data came from. Kubernetes artifacts, horizontal pod autoscaling on


queue depth, and a replicated ClickHouse cluster are the shapes this document deliberately does not draw


twice: they are well-trodden paths once the seams are respected.

12 Roadmap


The v1 platform is a complete, deployable loop from raw polls to operator screens. The roadmap prioritizes


fidelity of the flow signal over breadth of features, because flow is where the edge compounds.


•
 
v1.1 - Per-wallet fill mirroring.
 
Subscribe to Hyperliquid WebSocket userFills for the tracked elite


wallets to detect position opens, adds and flips at trade granularity instead of minute snapshots - the single


highest-leverage upgrade to flow accuracy.


•
 
v1.2 - Signal evaluation.
 
Score every emitted signal against the following 4h/24h price path using the


ClickHouse audit trail, producing per-family hit-rate and expectancy dashboards that inform threshold


tuning.


•
 
v1.3 - Cohort membership drift.
 
Track wallets migrating between cohorts (a rekt wallet healing into


profitable is itself a signal) and maintain a persistent elite universe independent of Hyperdash's snapshot


labels.


•
 
v1.4 - Scale-out.
 
Redis/Kafka work queues, sharded workers, WebSocket ingestion, Kubernetes


manifests - the seams documented in section 9.


The platform's contract is stable end to end: same API, same signal schema, same dashboard. Each roadmap


item tightens the loop between what the wallets are doing and what the operator sees - which was the entire


brief.
